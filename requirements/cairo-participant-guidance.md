## A. Project Description PDF Guidelines

**What it is:** the document that explains the project for Cairo judges: what you built, how it works, what
supports your claims. Made in any writing or design tool, exported as PDF.

| Item | Its job |
|---|---|
| Demo | Quick introduction: video ≤ 30 s or ≤ 7 slides |
| Project description PDF | The clear, detailed explanation of the solution |
| Actual project | The work judges can open, use or check |

- **Cairo local requirement.** NASA's global guide asks for Project-page fields and doesn't list a separate
  PDF upload as a global requirement.
- **No length limit** on the PDF (the 7-slide / 30-second limits are for the demo only). Keep it focused and
  follow any later Cairo instructions.
- **Write for a new reader:** simple English, technical words explained on first use; clear headings, short
  paragraphs; useful images, diagrams or screenshots, each with a short explanation; only claims you can
  support; names, facts, links and features **consistent** with the NASA project page, demo and project.

**Sections it should contain:**

1. **Project identity and short summary:** project name, team name, selected challenge. What did you build?
   What problem does it solve? How does it answer the challenge? Who could it help, and why does it matter?
2. **Project details:** what it does and how it works, step by step; one main task (what goes in, what the
   project does, what comes out); tools, coding languages, hardware or software; benefits and goals with
   evidence or examples; **clearly separate working features, limits or unfinished parts, and future plans**
   ("a prototype is an early version, so name it honestly").
3. **NASA data and resources:** for each one, its **name, source link and how it was used**, and how it helped.
   At least one NASA dataset/resource to qualify for a Global Award. Where relevant: mission/product, dates,
   area, and the steps used to prepare the data. List only resources actually used. "We used NASA data" alone
   is not enough.
4. **Other resources and source credits:** other agency data, tools, code, text, images, even free or open
   source: names, links and how used. Check licences and get permission when needed.
5. **AI and SI use:** say whether AI/SI tools were used; name each tool, its task and the affected work. If
   none, write **"No AI/SI tools used."**

**AI/SI rules repeated in it (from the NASA guide):** SI = "Super Intelligence" (machine learning, chatbots,
image generators, large language models). It may help develop the solution, but **must not come up with
your idea**. Generated images/video need a **visible watermark** saying SI generated them; generated audio
and code/data need an acknowledgement in the description and metadata. Generated content must not use,
include or change NASA branding (logos, flags, mission identifiers). **Privacy note:** NASA judges don't see
the SI-field answer, but Cairo judges **do** read the PDF and see the labels.

**Links:** include the NASA project page, demo and actual project. For interactive work, provide **a working
version Cairo judges can use**. A code repository alone doesn't open a running app; add setup/use
instructions where needed.

**Export, upload, test:**

1. Export as PDF and check every page (text and images readable, nothing cut off, links work). **A Word file
   is not the requested PDF.**
2. Upload to Google Drive or another host with a viewing link that needs **no login, password, registration
   or permission request**. Test it in a private/incognito window.
3. When Cairo submission opens, paste the PDF's public link into the **project-documentation field**. A file
   name or a path on your computer is not a public link.

Final check (from the PDF): English · project/team/challenge names · summary · details and limits · NASA
sources · other credits · AI/SI use · correct PDF · readable pages · tested public link.

## B. Demo Guidelines

| Format | Maximum length | Language |
|---|---|---|
| Video | **30 seconds or less** | English, or another spoken language with **English subtitles** |
| Slides | **7 slides in total**, including title and introduction slides | English |

- These limits are **official NASA rules**: a longer video or more than 7 slides makes the project
  **ineligible for Global Judging**. Don't add an extra title slide outside the 7.
- **Show the project:** team name, project name, selected challenge (slides: also members' names); the
  problem (who needs help, what's hard for them); the solution (the main action, result or finished work);
  how NASA or space-agency data helped; the benefit.
- **Honest and easy to follow:** show what works now; say when something is a prototype, a design only, or a
  future feature. "Do not make a picture of a feature look like proof that it already works." The demo
  supports the actual project; it doesn't replace it.
- **Suggested video timing** (a NASA storytelling tip, not a requirement): 0–2 s introduce yourself and
  team · 2–5 s challenge and why · 5–10 s project name and short description · 10–20 s how it works and how
  the data helps · 20–30 s benefit and future value.
- **Suggested 7-slide plan** (advice, not a template): 1 Introduce (project, team, members) · 2 Problem
  (challenge, who needs help) · 3 Solution (what, main purpose) · 4 Show it working (images, a main action
  and a result) · 5 The data (NASA/partner sources and their role) · 6 Progress (what works, evidence,
  limits) · 7 Value (benefits and clearly labelled next steps).
- **Readable:** large clear text, few words per slide, useful pictures; for video, clear speech and
  subtitles; no long intro that eats the time.
- **Content rules:** English slides (or English subtitles). **No images, video, audio or likeness of anyone
  under 18** (a content rule, not a participation ban: show the project instead of filming a minor). Credit
  outside images, music, text, even free/open source; check licences. SI images/video need a visible
  watermark; SI audio needs an acknowledgement in description and metadata. Explain AI/SI use in the project
  information; no NASA branding in generated content.
- **Upload and test:** host it externally (YouTube, Google Drive, GitHub, OneDrive, Dropbox): **NASA's project
  page doesn't accept direct video or slide uploads.** Viewing link with no login/password/registration/
  permission request; **don't give editing access** just to let judges view. Test in a private window that
  the full demo opens and sound, subtitles and slides work. Use the **same final demo link** on the NASA
  project page and in the Cairo local submission, consistent with the PDF and project.

Final check (from the PDF): correct length · clear project and challenge · useful visuals · correct
language/subtitles · source credits · AI labels where needed · public viewing link.

## C. Tips and Tricks session (video)

Presented by a Cairo organizer who was a virtual participant in 2024, a local winner and a global nominee.
They used their own 2024 challenge as the example. The auto-transcript garbles numbers and English words;
*(unclear)* marks what must not be relied on.

- **Read the challenge:** read all of Details, but go straight to the Objectives and cover as much of the
  target as you can; "the more you cover, the higher the score" (their claim).
- **NASA resources:** use the Resources tab; Cairo can't provide any resources, everything comes from the
  global site. Any dataset and any method is fine.
- **Final project link:** they linked their GitHub repo; "make a good repository that explains the project
  in detail". A website, app or model link is also fine.
- **Project details:** add screenshots of the UI with all details.
- **The demo trick:** they screen-recorded the working project, **sped it up, made it a GIF and put it in a
  slide**, with a short description beside it. That showed the UI and the idea and proved it runs. They
  stressed showing the work is grounded in science and NASA resources (for their ML part: dataset name and
  description, model accuracy, how it works, very briefly). Extras they documented: physical cards linking
  to the website, a marketing strategy.
- **Dates:** global submission opens "when the clock turns 12" on day "14" *(unclear)*. Our recorded
  official opening is **Sat Nov 14 9:00 a.m. Africa/Cairo** ([`competition-requirements.md`](competition-requirements.md)).
  Keep the official time until confirmed.
- **Local Cairo form:** released separately and announced on the **Discord** server.
- **Last tip:** study the past global winners (incl. the first global winner from Space Apps Cairo) and how
  they built their submission (30 s video vs 7 slides).
